# Employee rosters and compensatory off

On Attendances, in the Roster import section, authorized attendance editors can download a CSV template, choose a file, preview every validated row, and confirm the import. No CSV rows are written during preview. Imports are atomic and limited to 2 MB / 2,000 rows.

Accepted headers:

```csv
employee_id,date,day_type
EMP001,2026-10-18,Week Off
EMP002,2026-10-18,Working
```

Or, when employee codes are unassigned, use the Users directory's Sys ID:

```csv
user_id,date,day_type
92,2026-10-18,Week Off
133,2026-10-18,Working
```

Replace example identifiers with intended employees. Dates must be valid YYYY-MM-DD; day_type is exactly Working or Week Off. Unknown, unauthorized or ambiguous employees, duplicate employee/date rows and invalid values block the whole import. Reimport updates matching dates and preserves other dates. A day with Pending or Approved CO cannot change its day type. Import changes and CO decisions have actor/timestamp audit events.

The attendance calendar shows Working / Week Off markers for the selected employee, including dates without attendance. No weekends are assumed when no roster exists. Roster labels do not create attendance, mark absences, change shift calculations, or alter leave deductions.

Completed attendance automatically creates a Pending CO request for the employee on a rostered week-off date. Attendance saves cover employee checkout/logout, manual attendance entry and approved attendance corrections. Check-in alone does not create a request. Synthetic overnight rollover closures are excluded. No historical backfill runs when opening the page or importing rosters. Older records and rejected claims can use the manual request/resubmission form in Compensatory off. Eligible evidence is at least one non-deleted Present, Late or Half-Day attendance session with both check-in and check-out and unequal times. Overnight sessions are supported by existing attendance rules. There is no minimum duration, no CO expiry, and exactly one credit per employee/date. Future dates and incomplete attendance are rejected.

The current direct manager (attendance-edit permission and existing LOB restrictions) can approve/reject. Existing Admin / Super Admin / view-all-data authority is retained. Non-global self-review is denied. Pending requests leave balances unchanged. Approval rechecks roster and completed attendance and credits 1 to the employee's CO total_leaves in the same transaction as the decision and audit event. Repeated decisions and reimports cannot issue duplicate credit. Rejected claims can be manually resubmitted with history retained; attendance edits do not reopen rejected or approved decisions. Requests and decisions are visible in the CO panel with reviewer details and audit history.

CO is available through the existing active leave-balance selector and normal leave approval/deduction flow. Existing manual attendance/balance edit permissions remain in place. Later edits to attendance do not automatically reverse an already approved CO credit; any balance correction uses the existing authorized balance-edit process. Payroll, overtime, holiday, leave entitlement and attendance policies are otherwise unchanged.

## Release

Applied locally only:

```sh
php artisan migrate --path=database/migrations/2026_10_17_210000_create_employee_rosters_table.php --force
php artisan view:cache
npm run build
```

Deploy the new tables before application code/assets that query them. Refresh cached routes through the normal release process. Production has not been deployed.

## Attendance workspace arrangement

The redesigned page groups tools into Attendance, Corrections, Compensatory off, Roster import (attendance-edit only), and My leave balances. The attendance section retains employee context, full-result summaries, calendar/list toggle, filters, exports and record actions. Status counts are compact and keep their loaded-record semantics. Your leave balances always refer to the logged-in employee; correction/CO inboxes retain existing ownership/reviewer visibility rather than inheriting the attendance employee selector. Modals continue to work across sections. No new migration is required for the redesign or automatic requests beyond the existing roster tables.
