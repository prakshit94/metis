# Load test results — 2026-10-09

## Run setup

- Target: local Metis app at `http://127.0.0.1:8000`, `APP_ENV=local`, MySQL database `metis`.
- Load profile: k6 stress ramp to 68 virtual users for page and API traffic, run sequentially.
- Authentication: isolated temporary Super Admin load account. The account and its sessions, login history, attendance, role assignment, and related audit/activity entries were removed after the run.
- Traffic: GET requests only. No order, payment, customer, return, or inventory write workflows were submitted.
- The 68 VUs shared the temporary account's authenticated session. This measures concurrent requests, not 68 independently authenticated users.

## Results

| Profile | Coverage | Requests | HTTP failures | Average | p95 | p99 | Maximum |
|---|---:|---:|---:|---:|---:|---:|---:|
| Pages | 63 page routes, all returned HTTP 200; peak 68 VUs | 884 | 0% | 5.05 s | 12.45 s | 13.00 s | 13.27 s |
| APIs | 115 GET routes swept; peak 68 VUs | 1,815 | 0% | 2.14 s | 7.82 s | 10.47 s | 12.40 s |

The API checks reported no server errors. Some routes with placeholder resource IDs returned expected client responses such as 404 or 422; those are not evidence that the resource-specific workflow was successful. The suite excludes the external live-tracking lookup from repeated API traffic and excludes download/export routes from the repeated stress mix.

## Interpretation

Both profiles completed their route sweeps with no HTTP failures, but latency exceeded the suite's provisional thresholds at 68 VUs. The page p95 was 12.45 s against a 2.5 s stress threshold; API p95 was 7.82 s against a 5 s threshold. The local app was running under `php artisan serve`, so these results identify a local bottleneck and should not be treated as production capacity. A representative multi-worker deployment test with independent user sessions is needed to estimate production capacity.
